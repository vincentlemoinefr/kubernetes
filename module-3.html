Étape 01 · Poser la première pierre

Installer Minikube

On bâtit la résidence sur Ubuntu 22.04. Il faut trois outils, installés dans cet ordre :

1. Docker , le moteur de conteneurs. Minikube s'en sert comme « terrain » : l'immeuble entier tournera dans Docker. 2. kubectl , la télécommande pour parler au cluster (la voix du syndic, c'est vous). 3. Minikube , le programme qui construit et démarre la résidence elle-même.

Chaque commande de ce module est à copier-coller telle quelle. Si une étape échoue, on ne passe pas à la suivante : on relit le message d'erreur.

Côté résidence
Docker est le terrain et les fondations. kubectl est le téléphone qui vous relie au bureau de gestion. Minikube est l'entreprise de construction qui monte tout l'immeuble en une commande.
Étape 02 · Le moteur

A. Installer Docker

La méthode la plus simple et fiable sur Ubuntu : le script officiel de Docker. Copiez ce bloc entier dans un terminal.

1. Mettre la liste des paquets a jour $ sudo apt-get update 2. Telecharger et lancer le script officiel d'installation Docker $ curl -fsSL https://get.docker.com -o get-docker.sh $ sudo sh get-docker.sh 3. S'autoriser a utiliser docker SANS sudo (etape cruciale pour Minikube) $ sudo usermod -aG docker $USER 4. Activer ce nouveau droit dans le terminal courant $ newgrp docker 5. Verifier : doit afficher un message de bienvenue Docker $ docker run hello-world
Pour aller plus loin
La méthode « propre » en entreprise utilise le dépôt APT officiel de Docker (clé GPG + sources.list) plutôt que le script. Le résultat est le même ; le script est juste plus rapide pour un poste d'apprentissage. Si docker run hello-world ne marche pas, fermez puis rouvrez le terminal (le droit du groupe docker se charge à l'ouverture de session).
Étape 03 · La télécommande

B. Installer kubectl (+ confort)

kubectl (« koube-control ») est l'outil avec lequel vous donnerez toutes vos instructions au cluster. On l'installe, puis on ajoute deux conforts qui changent la vie : l'alias k et l'autocomplétion.

1. Telecharger la derniere version stable de kubectl $ curl -LO "https://dl.k8s.io/release/$(curl -L -s https://dl.k8s.io/release/stable.txt)/bin/linux/amd64/kubectl" 2. L'installer dans le PATH (accessible partout) $ sudo install -o root -g root -m 0755 kubectl /usr/local/bin/kubectl 3. Verifier la version du client $ kubectl version --client

Confort : un alias court et l'autocomplétion (touche Tab qui devine les commandes). À faire une seule fois :

Le paquet qui rend l'autocompletion possible $ sudo apt-get install -y bash-completion Alias : taper 'k' au lieu de 'kubectl' $ echo 'alias k=kubectl' >> ~/.bashrc Autocompletion de kubectl $ echo 'source <(kubectl completion bash)' >> ~/.bashrc Faire marcher la completion aussi avec l'alias 'k' $ echo 'complete -o default -F __start_kubectl k' >> ~/.bashrc Recharger le terminal pour activer le tout $ source ~/.bashrc Test : 'k ver' puis Tab doit completer en 'k version'
Étape 04 · La construction

C. Installer & Démarrer Minikube

On installe le binaire Minikube, puis on lance la construction de la résidence avec Docker comme terrain.

1. Telecharger Minikube $ curl -LO https://storage.googleapis.com/minikube/releases/latest/minikube-linux-amd64 2. L'installer dans le PATH $ sudo install minikube-linux-amd64 /usr/local/bin/minikube 3. Verifier $ minikube version 4. DEMARRER le cluster. C'est LA commande du cursus, a taper telle quelle. La 1ere fois prend quelques minutes. $ minikube start --driver=docker --cni=calico --cpus=2 --memory=3072 5. Verifier que le reseau Calico est bien en place (tous les pods Running) $ kubectl get pods -n kube-system | grep calico
Pourquoi ces trois options, et pas d'autres
--cni=calico : le plugin réseau ne peut pas être changé après coup. Sans lui, les Network Policies du module 12 seront acceptées par le cluster mais n'appliqueront aucun filtrage , on croirait avoir sécurisé quelque chose alors que tout passe encore. --memory=3072 : au jour 4, on ajoutera un second immeuble avec minikube node add, qui recopie ces réglages. 3 Go × 2 nœuds = 6 Go, ce qui laisse de l'air à Ubuntu. Démarrer à 4 Go rendrait le second nœud impossible. --driver=docker : on construit la résidence dans Docker, déjà installé à l'étape A.
Côté résidence
minikube start, c'est le jour de la livraison : l'entreprise coule les fondations, monte l'immeuble, installe le bureau de gestion et embauche le gardien. Le choix du CNI, c'est le choix du réseau de canalisations : on le coule dans les fondations, on ne le refait pas une fois l'immeuble habité.
Étape 05 · Vérifier & piloter

La Résidence est Debout

Quelques commandes pour confirmer que tout tourne et apprendre à allumer/éteindre la résidence.

Etat de Minikube : tout doit etre 'Running' $ minikube status La liste des immeubles : un seul noeud, statut 'Ready' $ kubectl get nodes Infos generales du cluster (adresses des services systeme) $ kubectl cluster-info Quel cluster pilote ma telecommande ? -> doit afficher 'minikube' $ kubectl config current-context L'adresse IP de l'immeuble Minikube $ minikube ip

Allumer, éteindre, détruire , sans perdre vos données entre deux sessions :

$ minikube stop # eteindre proprement (on garde tout) $ minikube start # rallumer la meme residence $ minikube delete # TOUT raser (a utiliser pour repartir de zero)
Étape 06 · Les équipements

Activer les Addons Utiles

Minikube propose des addons : des équipements préinstallés qu'on allume d'une commande. On active dès maintenant ceux dont la formation aura besoin.

Voir tous les addons et leur etat (active/desactive) $ minikube addons list Le hall d'accueil (necessaire au module 10 sur l'Ingress) $ minikube addons enable ingress Le compteur de consommation CPU/RAM (necessaire au scaling auto, module 5) $ minikube addons enable metrics-server Un tableau de bord graphique du cluster (confort, optionnel) $ minikube addons enable dashboard Ouvrir ce tableau de bord dans le navigateur $ minikube dashboard
Kubernetes réel
Ces « addons » sont une commodité Minikube. Dans un vrai cluster, on installe ces mêmes briques (contrôleur d'ingress, metrics-server, dashboard) à la main ou via Helm (module 13). Le confort de Minikube cache l'installation, mais ce sont exactement les mêmes composants tournant en pods.
Étape 07 · Le premier habitant

Votre Tout Premier Pod

Moment de vérité : on loge un premier habitant (un serveur web nginx) et on apprend les 5 commandes qu'on utilisera mille fois.

Creer un pod nomme 'web' a partir de l'image nginx $ kubectl run web --image=nginx Lister les pods (attendre la colonne STATUS = Running) $ kubectl get pods Tout savoir sur ce pod : les EVENTS en bas sont l'outil de debug n1 $ kubectl describe pod web Lire les journaux de l'application dans le pod $ kubectl logs web Entrer DANS le conteneur (un shell interactif) $ kubectl exec -it web -- bash # exit # pour ressortir du conteneur Supprimer le pod $ kubectl delete pod web
Côté résidence
run = emménager un locataire ; get = la liste des habitants ; describe = la fiche complète d'un appartement (avec l'historique des incidents) ; logs = écouter ce que dit l'habitant ; exec = entrer lui rendre visite ; delete = lui donner congé.
Étape 08 · QCM

Vérifiez vos Acquis

QUESTION 01
Ajouter son utilisateur au groupe « docker » permet d'utiliser Docker sans sudo, ce qu'attend Minikube.
Étape cruciale

Sans cela, minikube start --driver=docker échoue. Il faut parfois rouvrir le terminal pour que le droit prenne effet.

QUESTION 02
kubectl et minikube sont le même outil sous deux noms.
Deux rôles

minikube construit et gère le cluster local ; kubectl parle au cluster (n'importe lequel). kubectl fonctionne aussi sur un vrai cluster de production.

QUESTION 03
« minikube stop » éteint le cluster sans détruire son contenu ; « minikube delete » efface tout.
Exact

stop = pause, on retrouve tout au prochain start. delete = repartir de zéro. À connaître pour ne pas perdre son travail par accident.

QUESTION 04
« kubectl describe pod » affiche, en bas, des « events » très utiles au dépannage.
Le réflexe debug

Les events racontent l'histoire récente du pod (image téléchargée, échec, redémarrage…). C'est le premier endroit où regarder quand ça coince.

Étape 09 · Atelier

Atelier 3 : Bootstrap Complet de Zéro

Atelier 03 · Le grand copier-coller

D'une machine Ubuntu nue à un pod qui tourne

Ce script récapitule tout le module dans l'ordre. Sur une machine fraîche, il vous mène d'Ubuntu vide à un serveur web fonctionnel. Exécutez bloc par bloc, en vérifiant chaque sortie avant de continuer.

Phase 1 · Docker + kubectl + Minikube
$ sudo apt-get update && sudo apt-get install -y bash-completion curl $ curl -fsSL https://get.docker.com | sudo sh $ sudo usermod -aG docker $USER && newgrp docker $ curl -LO "https://dl.k8s.io/release/$(curl -L -s https://dl.k8s.io/release/stable.txt)/bin/linux/amd64/kubectl" $ sudo install -o root -g root -m 0755 kubectl /usr/local/bin/kubectl $ curl -LO https://storage.googleapis.com/minikube/releases/latest/minikube-linux-amd64 $ sudo install minikube-linux-amd64 /usr/local/bin/minikube
Phase 2 · Confort + démarrage + addons
$ { echo 'alias k=kubectl'; echo 'source <(kubectl completion bash)'; echo 'complete -o default -F __start_kubectl k'; } >> ~/.bashrc && source ~/.bashrc $ minikube start --driver=docker --cni=calico --cpus=2 --memory=3072 $ minikube addons enable ingress && minikube addons enable metrics-server $ kubectl get nodes
Phase 3 · Validation par un pod réel
$ k run web --image=nginx $ k get pods -w # -w = suivre en direct, Ctrl+C pour stopper $ k logs web $ k delete pod web
Validation

Réussi si : kubectl get nodes montre un nœud Ready, l'alias k fonctionne, et le pod web est passé par Running. Votre résidence est officiellement habitée. Gardez-la allumée pour le module 4.

Étape 10 · Conclusion

Récapitulatif du Module 3

  • Trois outils : Docker (le terrain), kubectl (la télécommande), Minikube (le constructeur).
  • Le droit docker : ajouter son user au groupe docker est indispensable avant minikube start.
  • Confort : alias k + autocomplétion = des heures gagnées sur 4 jours.
  • Cycle de vie : start / stop / delete, et les addons ingress + metrics-server activés pour la suite.
  • Cinq commandes reines : run, get, describe, logs, exec , la base de tout le reste.
Côté résidence
La résidence est construite, équipée, et un premier locataire y a vécu. On va maintenant comprendre en profondeur ce qu'est vraiment un appartement : sa structure, son cycle de vie, ses règles d'habitabilité.
